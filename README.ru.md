# acme-proxy

[🇬🇧 English](README.md) | 🇷🇺 **Русский**

Брокер DNS-01. Учётные данные DNS-провайдера хранятся у него, а не у его клиентов.

Клиент — обычно ACME-клиент, работающий на чём-то доступном извне, например в
панели управления, — просит acme-proxy опубликовать проверочную запись.
acme-proxy сверяет запрос с политикой этого клиента и пишет запись собственным
токеном провайдера. Клиент токена не видит никогда, и скомпрометированный клиент
может ровно одно: создавать ACME-записи для имён, которые ему разрешены.

acme-proxy ничего не выпускает. У него нет ACME-аккаунта, он не видит ни
сертификата, ни приватного ключа. Заказ, генерация ключа и CSR остаются на
стороне клиента.

## Зачем

Выдать смотрящему в интернет сервису DNS-токен с правом правки зоны — значит
отдать этому сервису зону целиком. Обычные обходные пути — второй аккаунт,
делегированная зона под `_acme-challenge` через CNAME — либо не уменьшают радиус
поражения, либо требуют по делегированию на каждое имя.

acme-proxy сужает выданное право до того, что реально нужно ACME:

- только TXT-записи, всегда — тип записи вообще не является частью API;
- только имена, начинающиеся с `_acme-challenge.` или `_validation-persist.`;
- только домены из списка разрешённых для этого клиента.

Первые два инварианта зашиты в код, конфигурацией их не ослабить.

## API

Аутентификация — `Authorization: Bearer <токен клиента>`. Ошибки приходят как
`{"error": "<код>", "message": "..."}` с кодами `unauthorized`,
`forbidden_domain`, `invalid_request`, `invalid_fqdn`, `no_zone`, `rate_limited`,
`provider_error`.

| Endpoint | Тело | Назначение |
| --- | --- | --- |
| `POST /v1/dns-01/present` | `{"fqdn": "_acme-challenge.a.example.com", "value": "..."}` | опубликовать проверочную запись; идемпотентно |
| `POST /v1/dns-01/cleanup` | `{"fqdn": "...", "value": "..."}` | удалить её; удаление уже отсутствующего — успех |
| `PUT /v1/persist` | `{"fqdn": "_validation-persist.example.com", "value": "..."}` | создать или обновить постоянную запись авторизации для `dns-persist-01` |
| `DELETE /v1/persist` | `{"fqdn": "..."}` | отозвать её |
| `GET /v1/policy` | — | что разрешено этому клиенту; клиент может показать это в своём интерфейсе |
| `GET /healthz` | — | проверка живости, без аутентификации |
| `GET /metrics` | — | Prometheus |

`present` добавляет запись, а не заменяет: заказ, покрывающий и `example.com`, и
`*.example.com`, порождает две TXT-записи с одним именем, и потеря одной из них
проваливает заказ. `PUT /v1/persist`, наоборот, заменяет — постоянная запись
авторизации на имя должна быть ровно одна.

Пример:

```bash
curl -s -X POST http://acme-proxy:8080/v1/dns-01/present \
  -H "Authorization: Bearer $CLIENT_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"fqdn":"_acme-challenge.edge.example.com","value":"K2s...43-chars"}'
```

## Конфигурация

См. [config.example.yaml](config.example.yaml). Секреты записываются как `${VAR}`
и подставляются из окружения; отсутствие переменной останавливает запуск.

Файл отслеживается. Изменение подхватывается в течение секунды, а конфигурация,
которая не разобралась или не смогла собрать своих провайдеров, попадает в лог и
**отбрасывается** — продолжает работать предыдущая. `SIGHUP` форсирует
перечитывание, что и нужно, когда файл примонтирован только на чтение.

Шаблоны разрешённых имён:

| Шаблон | Чему соответствует |
| --- | --- |
| `example.com` | ровно этому имени |
| `*.example.com` | `example.com` и любому поддомену на любой глубине |
| `node?-*.example.com` | glob внутри одной метки; количество меток должно совпадать |

`*.com` и прочие суффиксы из одной метки отвергаются: одна опечатка здесь выдала
бы право писать в чужую зону.

Зоны перечисляются для каждого провайдера и сопоставляются по самому длинному
совпадению, так что делегированная подзона выигрывает у родительской. Имя, не
попавшее ни в одну настроенную зону, отклоняется с `no_zone` ещё до обращения к
провайдеру.

## Провайдеры

В сборку входят `cloudflare` и `memory`. Слой провайдеров —
[libdns](https://github.com/libdns), поэтому добавление любого из примерно 95
существующих libdns-провайдеров сводится к импорту, ветке `case` в
`internal/providers/providers.go` и записи в `KnownProviderTypes`.

`memory` держит записи в процессе и забывает их при перезапуске. Он нужен для
тестов и для того, чтобы попробовать API, но никогда — для настоящего выпуска.

## Запуск

```bash
docker run --rm \
  -v /etc/acme-proxy:/etc/acme-proxy:ro \
  -e CF_API_TOKEN=... \
  -e CLIENT_TOKEN_PANEL=... \
  -p 8080:8080 \
  ghcr.io/nd4y/acme-proxy:latest
```

Не публикуйте его в интернет. Это сервис для внутренних клиентов: привяжите его
к приватной сети, а если сеть между клиентом и прокси не доверенная — поставьте
перед ним TLS.

## Разработка

```bash
go test ./...
go run ./cmd/acme-proxy -config config.example.yaml -listen :8080
```

С `type: memory` и парой переменных окружения весь путь запроса — аутентификация,
политика, провайдер — проходит локально, не трогая DNS.
